# Oasis Provider Compatibility & Inference Protocol Matrix

This matrix documents **verified** capabilities for every Oasis provider across both **Direct CLI mode** (Oasis v1.3.0 native monitoring & switching) and **Proxy mode** (`CLIProxyAPI-Rust` v0.3.2 / `b07936b`). Unsupported capabilities are explicitly marked and represented as such in the Oasis interface — never silently approximated.

## 2. Deep-Dive: OpenCode Go Per-Model Protocol Requirements

Audited directly from [`massiveits/opencode-go-cliproxyapi`](https://github.com/massiveits/opencode-go-cliproxyapi) (`v0.2.3`, `internal/catalog/catalog.go:125-140`, `internal/plugin/executor.go:148-158`, `internal/plugin/quota.go:21-79`):

OpenCode Go (`https://opencode.ai/zen/go/v1`) is **NOT** a uniform OpenAI Chat Completions endpoint. Different model families on the same gateway require different wire protocols and authentication headers:

| Upstream Wire Protocol | Gateway Endpoint | Auth & Required Headers | Model Prefixes (`catalog.go:125-140`) | Status in `CLIProxyAPI-Rust` Proxy |
|---|---|---|---|---|
| **OpenAI Chat Completions** | `POST /zen/go/v1/chat/completions` | `Authorization: Bearer <key>`, `x-opencode-session: <id>` | `deepseek*`, `longcat*`, `kimi*`, `glm*`, `mimo*`, `hy*` | **Supported via `openai-compatibility`** (explicitly scoped to these Chat models; note DeepSeek `developer`→`system` & `reasoning_content` shim and `x-opencode-session` require native provider support). |
| **Anthropic Messages** | `POST /zen/go/v1/messages` | `x-api-key: <key>`, `anthropic-version: 2023-06-01`, `x-opencode-session: <id>` | `minimax*`, `qwen*` | **Not supported via `openai-compatibility`** (would fail with protocol mismatch if routed to `/chat/completions`). Explicitly marked **Direct CLI / native `opencode` only** in Oasis until a native OpenCode Go provider lands upstream. |
| **OpenAI Responses** | `POST /zen/go/v1/responses` | `Authorization: Bearer <key>`, `x-opencode-session: <id>` | `muse-spark*`, `grok*`, `gpt*` | **Not supported via `openai-compatibility`**. Explicitly marked **Direct CLI / native `opencode` only** in Oasis until a native OpenCode Go provider lands upstream. |
| **Catalog Discovery** | `GET /zen/go/v1/models` | `Authorization: Bearer <key>` (no `x-opencode-session`) | Returns `{data: [...]}` with nested `limit.{context,output}` and `modalities.{input,output}` | Oasis can query catalog models when configuring OpenCode Go Chat models so only live verified Chat-protocol model IDs are exposed. |
| **Quota Usage** | `GET /zen/go/v1/usage` | `Authorization: Bearer <key>` | Rolling 5h, Weekly, Monthly windows | Already supported natively in Oasis `ai_limits.py`. |

**Design consequence:** Oasis NEVER exposes `minimax*`, `qwen*`, `muse-spark*`, `grok*`, or `gpt*` under OpenCode Go's `openai-compatibility` proxy group. Only explicitly verified Chat-protocol OpenCode Go models are eligible for proxy syncing, and the UI surfaces a clear capability badge explaining the protocol boundary.

## 3. Cross-Format Translation & Provider Restrictions

When `CLIProxyAPI-Rust` proxies a request:
- **Passthrough (zero translation):** Used whenever the client's API format matches the target provider's native wire format (`Claude` → `/v1/messages`, `Codex`/`Grok`/`Muse` → `/v1/responses`, `Antigravity`/`Gemini` → Gemini, `Kimi` → all 3, `Compat` → `/v1/chat/completions`).
- **Hub-and-spoke IR translation:** Converts requests, tool calls, reasoning/thinking blocks, cache hints, and SSE event streams across formats when calling e.g. GPT from Claude Code or Claude from an OpenAI SDK.
- **Safety invariants verified from `src/proxy.rs` & `src/upstream.rs`:**
  - Cross-provider thinking signatures (`cpx-` prefix) are stripped before reaching another vendor so Anthropic/OpenAI signature checks do not fail.
  - Retries happen **only before HTTP 2xx / first streamed frame** — partial streaming responses are never retried across accounts, preventing duplicated tool execution and duplicated billable completions.
  - Client 4xx validation errors (`400`/`404`/`413`/`422`) return immediately without failing over.
  - Explicit `provider/model` prefixes (`codex/gpt-6-astra`, `claude/claude-sonnet-5-5`, `antigravity/gemini-3.8-flash-high`) guarantee no silent provider substitution.
  - **Terms & Authorization Notice:** Proxy mode uses your own authorized accounts and keys strictly within provider limits. Oasis does not implement quota circumvention, account sharing, or unauthorized Cursor inference. Note that some Anthropic OAuth endpoints may challenge non-browser TLS fingerprints (standard `rustls`, as documented in `CLIProxyAPI-Rust` FAQ).
